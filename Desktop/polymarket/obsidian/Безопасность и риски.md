# Безопасность и риски

Этот проект работает с реальными деньгами на децентрализованной бирже. Неправильная настройка может привести к потере капитала.

## Основные риски

| Риск | Описание | Митигация |
|------|----------|-----------|
| **Утечка ключей Polymarket** | Если `.env` попадёт в чужие руки — злоумышленник может копировать сделки, выводить средства, торговать от вашего имени | Never commit `.env` to Git. Use `.gitignore`. Store keys in hardware wallet or secure vault. |
| **Дублирование ордеров** | Запуск нескольких экземпляров `copy_trader.py` приводит к дублированию сделок | Используйте `fcntl.lock` (уже реализован). Проверяйте `copy_trader.health.json` на наличие нескольких PID. |
| **Недостаток баланса** | Ордера могут не выполниться из-за нехватки USDC.e | Установите `RESERVE_CASH_USD=5.00` и `BALANCE_BUFFER_USD=1.00`. Проверяйте баланс ежедневно. |
| **Высокая волатильность** | Рынки Polymarket могут резко меняться — прибыль может быстро превратиться в убыток | Не копируйте сделки с высокой волатильностью (например, `5m`, `15m`), если не уверены. Используйте `SELL_ONLY_IN_PROFIT=1`. |
| **Ошибка в логике take-profit** | Автоматический take-profit может закрыть позицию слишком рано или слишком поздно | Тестируйте с `TAKE_PROFIT_DRY_RUN=1` и `PROFIT_TAKE_DRY_RUN=1` перед запуском. |
| **Привязка к PMTrackBot** | Если @PMTrackBot изменит формат сообщения — бот перестанет работать | Регулярно проверяйте, как выглядят новые сигналы. Добавьте логирование в `bot.py` для отладки. |
| **Сбой базы данных** | Повреждение `polymarket.db` приведёт к потере истории | Делайте регулярные бэкапы: `cp polymarket.db polymarket.db.backup.$(date +%Y%m%d)` |
| **Проблемы с API Polymarket** | API может быть недоступен или изменить структуру ответов | Установите `FETCH_RETRIES=2` и `HTTP_BACKOFF_SEC=1.0` для устойчивости. Следите за обновлениями `py_clob_client`. |
| **Задержки и проскальзывание** | Ордера могут исполняться не по ожидаемой цене | Используйте `COPY_ORDER_TYPE=FAK` для немедленного исполнения. Избегайте `GTC` на волатильных рынках. |
| **Зависимость от Python 3.13** | Некоторые библиотеки могут не поддерживать новую версию | Используйте `venv` и фиксируйте версии в `requirements.txt`. |

## Рекомендации по безопасности

### 1. Хранение ключей

- **Никогда** не коммитите `.env` в Git
- Добавьте `.env` в `.gitignore`
- Храните `.env` в зашифрованном хранилище (1Password, Bitwarden, GPG)
- Рассмотрите использование **hardware wallet** для хранения `POLY_PRIVATE_KEY`

### 2. Использование фундера (funder)

- Всегда используйте `POLY_FUNDER_ADDRESS` — это ваша основная кошелька для позиций
- Не используйте кошелёк, откуда вы выводите средства — создайте отдельный `funder` адрес
- Держите на `funder` только нужный капитал для торговли

### 3. Тестирование

- Всегда запускайте с `TAKE_PROFIT_DRY_RUN=1` и `PROFIT_TAKE_DRY_RUN=1`
- Используйте `COPY_NOTIONAL_USD=0.10` и `MIN_ORDER_SIZE=0.1` для тестов
- Сначала копируйте только BUY, выключите SELL: `COPY_SELLS=0`
- Проверяйте `copy_trader.health.json` после каждого теста

### 4. Мониторинг и уведомления

- Настройте Telegram-бота для уведомлений о критических ошибках
- Добавьте мониторинг `copy_trader.health.json` через `cron` или `netdata`
- Настройте алерт при падении баланса ниже $10
- Используйте `HEARTBEAT_SEC=60` и проверяйте, что файл обновляется

### 5. Дополнительные меры

- Установите `WATCH_ONLY_WALLET` для мониторинга только одного проверенного кошелька
- Используйте `ALLOWED_MARKET_KEYWORDS` для фильтрации только надёжных рынков
- Отключите `AUTO_SELL_AFTER_BUY_ENABLE` — это опасная функция
- Не запускайте систему на общедоступных серверах — используйте только собственные машины или VPS

> **Критически важно:** Этот проект — **не инструмент для обогащения**, а инструмент для **автоматизации рискованной стратегии**. Никогда не вкладывайте больше, чем готовы потерять. Все сделки выполняются на децентрализованной бирже без защиты от ошибок.
